## Rules every item inherits (Decided)

1. **Same-binary A/B for every extraction-path change.** Freeze, measure and inspect per the
   [maintenance contract](benchmarks/README.md#benchmark-maintenance-contract). A change downstream of
   the OCR text is measured by [replaying a captured run](benchmarks/README.md#replaying-a-captured-run):
   one live capture, then every arm reads the same text.
2. **Narrow fixes under ADR-0021 need a correct→refused crosstab.** Each is gated on the
   real-specimen run with a correct→refused crosstab keyed by `asset_id`
   ([ADR-0021](decisions/ADR-0021-fixed-grid-mrz-strips.md), Phase 0 results, the maintainer's
   2026-09-24 decision).
3. **Synthetic can only veto.** Synthetic evidence can stop a reader change but never promotes one
   ([ADR-0021](decisions/ADR-0021-fixed-grid-mrz-strips.md), default-on item 4).
4. **Re-bless in the same PR.** A PR that moves an outcome count re-blesses the baseline in that PR,
   from the CI artifact ([`CONTRIBUTING.md`](../CONTRIBUTING.md), "The real-specimen regression gate").
5. **CI timings are diagnostics.** No CI timing is a result, and a value that depends on the OCR
   budget is measured locally ([ADR-0027](decisions/ADR-0027-ci-runners-measure-public-benchmark-arms.md),
   decisions 3 and 6).
6. **Refusing a wrong read is a correctness gain.** Refusing a checksum-consistent wrong read is not
   a regression ([ADR-0021](decisions/ADR-0021-fixed-grid-mrz-strips.md), default-on item 2). The
   precedent is Bosnia 2013, which #440 refused
   ([ADR-0011](decisions/ADR-0011-split-m6-packaging-into-m8.md), 2026-09-27 amendment;
   [FINDINGS.md](benchmarks/FINDINGS.md), 2026-09-24).

## 3. Strategic tensions

**T1. Refusals lower the headline, and the headline is the product claim.**

- **Already decided.** A refused manufactured hit is not a regression (ADR-0011, 2026-09-27
  amendment; ADR-0021, default-on item 2). M6 is closed, and scored misses that later cohorts add do
  not reopen it (ADR-0011, 2026-09-17 amendment).
- **The gap.** A miss created by a refusal is not a cohort addition, and the
  [post-M6 residual](benchmarks/README.md#post-m6-residual) has no place for one.
- **What (a) does not do.** It corrects the scoreboard, not the output. Until (b) and (c) are on,
  the reader still returns a checksum-valid read for Russia 2013 and Switzerland 2003 that the
  printed zone cannot support, and #443's report-only warning names them. (a) must not be described
  as a correctness fix.
- **The design.**
  - One refusal per PR.
  - A dated FINDINGS entry per refusal: the document, why the hit was never real, both
    denominators.
  - The re-bless in the same PR.
  - A residual line for misses a refusal creates (draft in the appendix).
  - Each refusal sits behind its own `SYNTHPASS_MRZ_*` arm, so one environment variable reverses
    it.
- **Modelled** for all three once (a), (b) and (c) are done: three hits leave the numerator, and
  two documents leave the denominator
  ([`wrong-physical-line1-2026-09-28.md`](benchmarks/wrong-physical-line1-2026-09-28.md), question 2).

**T2. The breaking-release cadence against `mrz`'s own path to 1.0.**

- **What the crate's roadmap says.** [`crates/mrz/ROADMAP.md`](../crates/mrz/ROADMAP.md) ("0.9.0 —
  release candidate") says *"Nothing breaks after 0.9.0, and the 0.9 line exists to prove that"*.
  The first item on its 1.0 checklist is that the 0.9.x line shipped with no further break.
- **The conflict.** The owner decided on 2026-09-30 that C6 ships with the 0.10.0 refusals. A
  0.10.0 reopens the breaking window a second time and restarts the 1.0 clock. Until the crate's
  roadmap says so, a tracked document and a decision disagree.
- **The design.**
  - Land each refusal as an opt-in `ParseOptions` switch. That is additive, because `ParseOptions`
    is `#[non_exhaustive]` with a builder ([`ARCHITECTURE.md`](ARCHITECTURE.md) §13.4).
  - SynthPass turns it on through an arm, as #574 did with `select_line1`, which nothing in `mrz`
    calls.
  - Collect every breaking change into one 0.10.0, following the crate's own "break once" rule.
  - Cut 0.10.0 only after (d) is decided.
  - Amend `crates/mrz/ROADMAP.md` before or with the release.
- **What this buys.** SynthPass's correctness gain no longer waits for the crate's release
  cadence, and a downstream user of `mrz` 0.9.x never sees a new refusal.

**T3. Synthetic results do not transfer to real documents.**

- **The record.** The chargrid A/B netted +30 strict names on synthetic and 0 net on real specimens
  ([reconciliation](benchmarks/chargrid-ab-reconciliation-2026-09-24.md)).
- **The atlas is weaker evidence still.** The atlas note says it is an oracle crop on synthetic
  renders, not a decode and not print
  ([`glyph-atlas-p-filler-2026-09-30.md`](benchmarks/glyph-atlas-p-filler-2026-09-30.md), "What this
  does not say").
- **#604 changes the generator, not the reader.** So the real gate cannot move on it.
- **The design.**
  - Judge #604 on fidelity to the print geometry already measured
    ([`ocrb-filler-geometry-2026-09-23.md`](benchmarks/ocrb-filler-geometry-2026-09-23.md)), and on
    an explained M4 movement. Do not judge it on the synthetic hit rate.
  - Any reader change the atlas motivates goes through the real gate, with synthetic as veto only
    (rule 3).

**T4. The generator has to hold still for M8's goldens while the #411 fidelity work continues.**

- **The constraint.** ADR-0022 decision 6 records golden hashes before the change. A pixel change
  between M8 PR 0 and PR 4 invalidates them.
- **The dependency.** #604 is frozen until the laptop's atlas A/B, and the M8 "go" waits on #604.
- **The design (Proposed).** Decide #604 by 31 October. If it is still open then, M8 PR 0 goes
  ahead on today's pixels. #604 and #411 PR 3 then wait until after PR 4, and the goldens are
  re-recorded in one deliberate PR.
- **The rejected alternative.** Landing the raise as a default-off render option keeps M8 unblocked
  but adds a generator knob that nothing else needs, a speculative abstraction.

**T5. One laptop carries most of the measurement.**

- **The design.**
  - Run the laptop queue in section 1's order.
  - Use replay for every change downstream of the OCR text, so one capture serves several arms.
