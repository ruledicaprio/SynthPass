# Developer and corpus-maintenance tools

These Python scripts are developer and corpus-maintenance tools only. They are never on the extraction path: the root README's **No Python** claim describes the Rust extraction runtime, not acquisition, review, tests, or CI maintenance. Some tools invoke the Rust OCR executables to inspect candidate specimens; extraction never invokes these Python scripts.

The [specimen-acquisition loop](../knowledge/SPECIMEN_SOURCES.md) defines the review gates and tooling boundary. Its [admitting a batch procedure](../knowledge/SPECIMEN_SOURCES.md#admitting-a-batch) explains the handoff from [apply_cohort.py](apply_cohort.py) (reviewed packet to cohort PR) to [rebless.py](rebless.py) (cohort PR to baseline and review readiness). The [real-specimen gate procedure](../knowledge/benchmarks/README.md#the-per-pr-real-specimen-regression-gate) documents re-blessing; consult the scripts' module docstrings for options and approval gates (`--help` is available on the maintenance command-line entrypoints other than the Commons downloader).

| [ocrb_metrics.py](ocrb_metrics.py) | Measures the vendored OCR-B font's per-glyph geometry over the MRZ alphabet (ink box, holes, ink area, straight-outline share, scanline ink runs) and ranks what separates each `mrz::CONFUSABLES` pair and the filler pairs, next to chargrid's `DEFAULT_INK_FLOOR`; run manually when working on glyph-level repair. | [classify_mrz_mechanisms.py](classify_mrz_mechanisms.py) | Joins an MRZ dump to its outcome ledger, verifies the dump's run, and classifies review targets with string-level candidate explanations ranked by edit cost, not observed physical mechanisms; run during local MRZ evidence analysis. | [bench_ab_args.py](bench_ab_args.py) | Validates dispatched benchmark A/B inputs into a normalized plan. `corpus=synthetic` retains the original plan and invocation; `corpus=public` requires default synthetic parameters and runs `provider-bench --real-specimens --mrz-only --write-text-free-outcomes` with both console streams discarded. | [bench_ab_diff.py --public](bench_ab_diff.py) | Reads only enumerated outcome, miss-kind, format, check-state and boolean columns from `real-specimen-outcomes-text-free.jsonl`, joins by public asset ID and emits counts and transitions. Ignores reason text and unknown columns; validates every emitted value. `--expect-identical` returns 0 and NEUTRAL for identical projections, 3 for differing projections, 2 for invalid data. |
| [test_bench_ab_public.py](test_bench_ab_public.py) | Hand-built public A/B tests: corpus refusals, fixed-population parameters, discarded console streams, planted reason/unknown-column text, and identical/differing per-asset verdicts. |
| [bench_ab_diff.py](bench_ab_diff.py) | Compares two benchmark arms document by document. An arm is one directory of `synthpass-bench` reports, one per format, plus a `real/` `provider-bench` run. For each format it prints hits, strict names, accepted reads (#578) and the accepted reads with a wrong document code or issuer. It lists every seed whose read changed, including the ones whose `synth_ab_diff` state did not move, with its miss kind, `retry_stop` and zone in each arm. For the real run it prints every changed outcome, names result and zone, with each zone's fixture agreement, plus an alarm on any false positive. From `report.json`'s per-document `field_correctness` (#574) it prints, per field, how many documents went exact to wrong, wrong to exact, exact to unread and unread to exact, and names each document with an exact field that stopped being exact, by asset id and field name and never by value; an arm without the maps prints "not recorded". From `report.json`'s `mrz_line1_select_arm` and per-document `line1_selection` (the line-1 selector, #574, on by default and measured) it prints each arm's selector arm and verdict counts, the asset ids with `applied`, `proposed` or `ambiguous`, and a flag for every asset `proposed` in one arm and neither applied nor proposed in the other, all by verdict name and asset id and never a line of text. It counts seeds that changed only in flags, fails when the two real runs measured a different corpus or different images, and, for an arm measured with a private or local track (`--include-private` or `--include-local` in the run archive, or a `private/` or `local/` asset), replaces the per-document lines with per-field value counts and enumerated transitions such as `mrz_format 1 × TD3 to MRVA`, with no asset name, image hash or `miss_reason` text (ADR-0024 Decision 7); `--asset` and `--expect-identical` still refuse such an arm. Run it manually after any A/B of the extraction path, so every flip can be attributed. `--expect-identical` is its neutrality mode for a change that should move nothing: exit 0 if every document reads the same, 3 if not, with counts and ids only and never OCR text; `--check-pass-trace` adds the pass-trace invariants, and `--check-report` compares each document's `report.json` row too, the fields the ledger and dump lack. Between a capture and its `provider-bench --replay-ocr-passes` replay it can reach NEUTRAL, since only `ocr_ms`, the run manifest's name and the pass trace the replay does not write differ; each arm's identity block prints the replay's `replay_of`. |
| [archive_query.py](archive_query.py) | Reads the per-document benchmark archive that `provider-bench` and `synthpass-bench` write after every run ([ADR-0024](../knowledge/decisions/ADR-0024-per-document-benchmark-archive.md)), read-only and standard library only, so a question about what OCR read is answered from runs already made. `runs` lists the finished run files (id, binary, start, commit, scope, record count, providers) and counts the `*.partial` files it skips; `diff A B` names the header arms that differ (a differing OCR model file as `model_sha256.<key>` 12-character prefixes), then joins the two runs' documents (a real specimen on `source_sha256`, so a rename keeps its key, else `asset_id`, else `name`; a synthetic seed on format, profile and seed) and prints the documents in one run only, the outcome changes, the per-field changes of the ledger row (the field classes are `rebless.py`'s, imported; timing and budget-limited documents kept apart), how many recovered zones differ and at which cells, and the `truth` mismatch-count deltas; `cell RUN --line L --col C` counts the classes (letter, digit, filler, other, absent) at one cell of the recovered zone across a run, the question ADR-0021 asked; `codes RUN [RUN2]` is the document-code witness matrix ([#664](https://github.com/ruledicaprio/SynthPass/issues/664)): per provider and format, the printed code's two cell classes (`truth.code_cells`, `A<` for `P<`, `AA` for `PS`) against the observed ones (the first two cells of the recovered zone, `unread` when nothing was read), the code's `document_type` exact / wrong / unread per printed class, the retry variant and stop of the reads whose class differs, and the asset ids of the public documents that differ (a local or private record is counted, never named); with `RUN2`, both matrices side by side and the documents whose observed class changed, and two runs that are not comparable (binary, models, scope, tracks, providers, data, corpus manifest, replay source, one-to-one document set) are refused. It prints asset ids, field names, enumerated values, counts, positions and classes, and never OCR text, a zone line, a field value, `argv`, `model_paths` or a `miss_reason` text; `--chars` is the one opt-in and refuses any run that is not public (a file in `local/`, or any record whose `track` is not `public`, `covers` or `synthetic`). Reads `public/` by default (`--track local` for the other), schema 1 only; exit 0 for a report, 2 for a usage, I/O or schema error. |
| [promotion_gate.py](promotion_gate.py) | The read-only arm-promotion gate ([#664](https://github.com/ruledicaprio/SynthPass/issues/664)): `check BASE CANDIDATE CANDIDATE [...] --declare FILE` reads one base run and two or more candidate runs from the archive (public or local track, never `private/`) and refuses unless they are comparable (the binary and each OCR model file by SHA-256, the scope, the arms and the images), vetoes a lost hit, a new false positive or document-number mismatch, a field that stops being exact, a lost exact name or repeats that disagree, and otherwise checks the declared target. Read-only, standard library plus `archive_query`; prints ids, field names, counts and the declaration's hash only. See `knowledge/benchmarks/PIPELINE.md` §2.6 |
| [bench_nightly_rows.py](bench_nightly_rows.py) | The nightly benchmark's row extractor and the one reader of `bench-data`'s schema-2 files ([ADR-0027](../knowledge/decisions/ADR-0027-ci-runners-measure-public-benchmark-arms.md)). `assemble` projects each `synthpass-bench` report to allowlisted rows (`fresh.jsonl`, `fixed.jsonl`) and run headers (`runs.jsonl`), refuses any key outside the allowlist and any value that could carry text, and fails when the flags recomputed from the rows (wrong accepts, strict names, accepted reads, prefix counts) differ from the report's own counts; `guard` refuses a repeated `(document_type, seed, profile)` in `fresh.jsonl`; `next-seed` picks a format's next fresh seed; `context` records the runner's CPU, core count, `rustc` and model hashes. `read_rows` reads the frozen schema-1 `dataset.jsonl` under its reading rule. Called by [bench-data-collection.yml](../.github/workflows/bench-data-collection.yml); never on the extraction path, and it prints no report value. |
| [bench_nightly_advisory.py](bench_nightly_advisory.py) | The nightly advisory ([ADR-0027](../knowledge/decisions/ADR-0027-ci-runners-measure-public-benchmark-arms.md) decision 7). Reads `fresh.jsonl`, `fixed.jsonl` and `runs.jsonl` through `bench_nightly_rows`, pairs the fixed slice per seed against the last night with the same generator fingerprint and names every flipped seed, and tests the fresh slice's last 7 nights against the prior 28 with a two-proportion z-test. Writes a job summary, one `::warning::` per flag and one aggregate line per night to `advisory.jsonl` (counts, rates, z values, codes and seed numbers only). Exits non-zero only for a new wrong accept or prefix-wrong read on a fixed seed, or an invalid measurement. Stdlib only. Called by [bench-data-collection.yml](../.github/workflows/bench-data-collection.yml); see [the nightly advisory](../knowledge/benchmarks/README.md#the-nightly-advisory). |
| [bench_nightly_intervals.py](bench_nightly_intervals.py) | Reads a checkout of `bench-data` and prints, per format and per profile, the Tier-1 hit rate, the share of hits wrong on at least one scored field and the share wrong on each of the 12 scored fields, each with its n and a 95% Wilson interval (the same interval `synthpass-bench` prints). Nights pool only when the generator fingerprint, the OCR model hashes, the OCR and MRZ arms and the retry budget and time limit all match, so a re-render or a new model starts a new pool; the fresh slice is pooled across a pool's nights, the fixed slice never is (the same 100 seeds add no n), and it says whether every night read every seed identically. `retry_stop` budget rows are left out of every rate and counted on their own line. Markdown on stdout, or `--json`; aggregates only, never a per-document record. Reads the rows through `bench_nightly_advisory` and `bench_nightly_rows`, which it does not change. Run it manually after pulling `bench-data`; comparing two pools is the advisory's z-test, not two overlapping intervals; see the method note *Intervals in the synthetic summary* in [knowledge/benchmarks/README.md](../knowledge/benchmarks/README.md). Stdlib only. |

Run the maintenance tests from the repository root:

```sh
python -m unittest discover -s tools -p 'test_*.py'
```

CI runs the same command on every pull request (the offline tools job in [ci.yml](../.github/workflows/ci.yml), which installs no Python packages). The tests do not run a corpus measurement. The Commons downloader requires `requests`; the screener's optional PDF lane requires PyMuPDF. Other maintenance scripts use the Python standard library, with external commands required by their individual procedures.

[scout_prefix.txt](scout_prefix.txt), [host_denylist.json](host_denylist.json), and [legal_portals.json](legal_portals.json) are supporting scouting and screening inputs, not executable scripts.
