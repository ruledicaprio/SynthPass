- **The extraction path never downloads OCR models.** Before this change, a missing `.rten`
  weight file was fetched lazily the first time `synthpass <file>`/`batch` ran, unless
  `SYNTHPASS_OCR_AUTO_DOWNLOAD=0` was set — a runtime default that contradicted the documented
  "no runtime downloads on the extraction path" contract (`knowledge/project_principles.md` #5,
  README's "zero cloud calls"). `SYNTHPASS_OCR_AUTO_DOWNLOAD` is gone; if it's still set,
  `synthpass` logs one warning that it no longer has any effect. Extraction now fails closed
  with a message naming the fix (exit 1, same as any other runtime failure) when a model is
  missing, and `doctor`'s missing-model line names the same fix.
  **What to run instead:** `synthpass fetch-models`. In the default build it prints each
  model's pinned URL and SHA-256 plus the target directory (`SYNTHPASS_OCR_MODEL_DIR`), so you
  can fetch and verify manually, e.g. `curl -fL -o <dir>/text-detection.rten <url>` then
  `echo "<sha256>  <dir>/text-detection.rten" | sha256sum -c -`. A build with the new,
  non-default `download` cargo feature (`cargo build --features download`, propagated through
  `synthpass-pipeline`/`synthpass-cli`) downloads and verifies both files itself. `reqwest` now
  lives entirely behind that feature, so a default binary has no HTTP client in its dependency
  graph at all (#491).
