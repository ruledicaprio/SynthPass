- **The line-1 selector is now on by default, and the pipeline's v1 record follows the same Tier-1 read as the v2 record.** `SYNTHPASS_MRZ_LINE1_SELECT` now defaults to `on` (`Line1Arm::default()` is `On`, and an unset, empty or unrecognised value means `on`). When Tier 1 accepts a TD3, TD2, MRV-A or MRV-B zone whose line-1 name field breaks the name grammar, and the same OCR text holds exactly one other qualifying line, that line replaces line 1, so `surname`, `given_names` and line 1 of `mrz_lines` can differ from the previous release for such a read. A text whose accepted name field is grammatical reads as before, non-name fields never change, and no OCR runs. On the real specimens the measurement (`knowledge/benchmarks/line1-selection-ab-2026-09-29.md`) changed no outcome and no correct field, and moved strict names from 13/45 to 15/45; every synthetic format was identical seed for seed. `SYNTHPASS_MRZ_LINE1_SELECT=off` restores the previous read, and `control` stays available as a placebo. `PipelineResult.mrz` and the v1 `extracted` record now come from `synthpass_die::read_tier1` too, so the v1 and v2 records carry the same names under every arm; the Tier-2 hint is built from that read as well, but carries check-digit fields only, which the selector never changes. `trace.config_overrides` now lists `SYNTHPASS_MRZ_LINE1_SELECT` when it is not `on` (it used to list it when not `off`), and `provider-bench --write-baseline` and `--assert-baseline` refuse any value but `on` (#574).
