- **Tier 1 no longer accepts a document number misread with a leading filler.** `<00000220` and
  `K00000220` are checksum-indistinguishable (`K` and `<` share residue 0 at every 7-3-1 weight),
  so a misread first character used to still validate. `mrz` 0.9.0 refuses this outright as
  `MrzError::LeadingFiller`, a structural error; the OCR retry loop's stop test and the pipeline's
  Tier 1 already treat any `mrz` `Err` as "keep looking", so both pick this up with no code change
  of their own. `synthpass-bench`/`provider-bench` report it as its own miss bucket,
  `document_number_leading_filler`, inside the Tier-1 denominator (#536).
