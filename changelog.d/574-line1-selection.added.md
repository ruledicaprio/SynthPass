- **`SYNTHPASS_MRZ_LINE1_SELECT` (`off`, `control` or `on`) adds a shadow line-1 selector to Tier 1, and it is off by default and unmeasured.** With the arm not `off`, `synthpass-die`'s new `read_tier1` runs `mrz::select_line1` on the read `mrz` accepted. When a TD3, TD2, MRV-A or MRV-B name field breaks the name grammar, it looks in the same OCR text for exactly one other line of the same width, document code and issuer whose name field is well formed. `control` records the verdict and discards the proposal; `on` applies it. It changes `surname`, `given_names` and line 1 of `mrz_lines` only, and runs no OCR. `MrzReader`, the synthetic benchmark's Tier-1 read and `provider-bench`'s dump zone read through it (the OCR retry loop's own parse, the Tier-2 hint parse, the `mrz_found` parses and the printed-zone validity parse do not). `Evidence` gains a text-free `line1_selection`. Both `SYNTHPASS_MRZ_*` arms are now recorded in `trace.config_overrides` (`synthpass_die::mrz_config_overrides`) when not `off`, `--write-baseline` and `--assert-baseline` refuse a non-default value of either, and the report carries `mrz_line1_select_arm` in both benchmark binaries (the synthetic report also gains `mrz_class_sweep_arm`). With the arm not `off`, `provider-bench`'s `documents_detail[].line1_selection` and the provider row's `line1_selection_counts` report the verdict by kind, count and pass id, and the OCR-dump run manifest gains `mrz_arms`; `tools/bench_ab_diff.py` prints them and flags an asset `proposed` in one arm and neither applied nor proposed in the other. With every arm `off`, the reads are unchanged. Under `on` the pipeline's own `mrz::find_and_parse` (the v1 `extracted` record and `PipelineResult.mrz`) is not routed through the selector, so the v2 record can carry names the v1 record does not (#574).
