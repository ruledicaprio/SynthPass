- **`ParseOptions::date_digits` (with `with_date_digits(bool)`) makes a read whose date of birth or date of expiry holds a character other than an ASCII digit or `<` not `valid()`, and it is off by default and unmeasured (#579, the C6 rule).** A check digit is arithmetic and letters have values too, so a zone whose date of birth is six letters can pass every check digit. With the option on, `valid()` also requires both dates to hold digits or fillers only; `checks` and `checksum_consistent()` still report the arithmetic unchanged, and a partially unknown or all-filler date stays valid. `MrzData` gains `date_digits_required` (recorded at parse time, because `valid()` takes no options): it is `false` for every read made with the default options and is left out of the serialized JSON unless the option was on, so default output is byte-identical and older JSON still deserializes. Only the two date fields are affected. The option ships first so an A/B can name it; the 0.10.0 refusals will flip the default after it is measured.
